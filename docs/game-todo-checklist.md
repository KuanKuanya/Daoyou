### 4. 经济、奖励与周期边界

本轮已落实的代码基线：

- ✅ 拍卖竞争、卖家下架和过期任务均通过 `status = active` 的数据库条件更新决定唯一胜者；购买扣款、货单扣量和邮件发放在同一事务内完成。
- ✅ 购买、上架、下架、回收和宗门兑换均接入玩家命令幂等记录；响应丢失后使用同一请求键重试不会重复执行已提交写入。
- ✅ 回收报价通过 Redis 10 分钟 TTL、物品 revision 和快照比对保护；拍卖 48 小时到期边界已统一为 `expiresAt > now`。
- ✅ 蜃楼每周奖励以角色行锁、奖励收据和战斗回放归档共同去重；同场重试不会再次发放奖励。

## 六、当前明确不列入待办的产品取舍

以下是已经确认的范围，不应因为“看起来少了功能”而自动重新开发：

- 不做离线挂机和服务端持续托管 AUTO。
- 不恢复旧 V5 战斗、旧聊天战报和旧分享接口。
- 不恢复道装品质、评分、淬炼、耐久、负属性、套装和鉴定。
- 不增加灵兽后天技能格、指定打书、锁技能和保底。
- 不恢复旧六道印覆盖；功法继续独立培养、同境界一本生效。
- 不默认增加散修独立成长线。
- 不默认展示精确掉落概率、保底或热更新后台。
- 不因为 Redis 进度丢失就允许资产重复发放。
- 不把基础代码存在、共享测试通过或一次浏览器流程通过，等同于全玩法完成。
