# 本地项目工作台

运行 `pnpm run workbench`，打开 `http://127.0.0.1:5180`。工作台独立于游戏和数据库，仅绑定 loopback，固定端口，并校验写入请求的 Host / Origin。不要通过反向代理公开这个端口。它不是生产后台，不随游戏构建部署。

## 索引范围与口径

- 内容：扫描 `packages/game-content/src` 中非 Schema JSON 的具名 ID 对象；包含灵兽、技能、功法、宗门心法、分支、状态、地图节点和其他具名内容。嵌套对象单独计数，不等同于玩家可学习技能总数。
- 宗门与物品：启动前构建内部库，读取现有运行时目录。显示聚合入口与完整定义，静态引用可定位具体文件。外部修改 TypeScript 内容后，重新运行命令以更新这些编译目录。
- 素材：扫描 `apps/web/public` 中的图片、音频及字体；包含地图、图标和立绘。
- 引用：用 TypeScript AST 扫描 content、rules、Web、API 的字符串字面量。支持 ID、图标名称与完整资源路径的反查；不推断动态拼接或外部引用。未发现引用不是确认闲置，更不是自动删除依据。
- 不读取环境文件、账号、玩家库存或数据库实例。不将静态内容复制进数据库。

## 编辑与替换

灵兽物种、灵兽技能、个人功法的名称／描述及已存在的图标字段支持表单编辑，保存前调用原有 `loadBeastPacks` / `loadManualPack` 校验。ID、机制数值、复杂宗门规则保持只读。修改灵兽内容会递增对应内容修订号。

修改某个内容的 `icon` 只改变它的绑定。进入图标条目替换素材则影响该名称的全部引用；保存确认显示影响范围、新旧对比。可选择现有图标文件，或上传不超过 5 MiB 的 PNG / WebP。上传以内容哈希命名，不覆盖已有素材；旧文件保留供撤销与引用检查。图标小尺寸预览和内容图标使用现有渲染入口，资产浏览直接展示原文件。

保存检测源文件 SHA-256，拒绝覆盖打开后发生的外部修改；同一进程的修改串行执行，单个文件通过临时文件 rename 写入。撤销仅覆盖本次工作台进程的最近一次保存，且再次检查文件版本，不执行 Git reset。撤销图标绑定不会删除上传文件，它会留在资源目录供后续人工整理。

源码写入成功不等同于运行时已生效：图标注册变化会触发 Vite 更新；内容包修改需构建依赖库，并重启运行中的 API。工作台不自动重启游戏服务。修改后按影响范围运行 lint、typecheck、build 与相关纯规则测试，再到游戏确认。

## 地图校准

地图页从 `packages/game-rules/src/world/mapAtlas.ts` 的静态配置读取世界入口、区域归属和锚点，从 `AtlasPhaserRuntime.ts` 读取实际底图绑定，不使用另外一套编辑器坐标。节点列表采用游戏展示地域，包含南疆与北境。

选择区域后，地图叠加该区域的地点。选择列表节点会切换到所属区域并突出锚点；打开“调整锚点”后可拖动标记，或输入 X / Y 相对坐标。左上为原点，坐标必须严格在 0 与 1 之间。画布固定为游戏当前的 1536 × 1024；编辑器与游戏采用相同的图片拉伸方式。缺失锚点可通过节点选择框和数值输入补齐。

坐标保存前显示新旧值，检查地点源文件、锚点配置、底图绑定以及底图文件 SHA-256，拒绝同路径图片被替换后的旧草稿，并通过 AST 定位修改现有配置，不执行源码表达式。保存后需重建 game-rules（重新启动 `pnpm run workbench` 会构建依赖，游戏开发服务也可由 turbo watch 更新）。

候选底图可以直接带当前锚点预览，但只有“确认接入底图”保存后才会修改游戏绑定。底图和坐标分步保存，禁止在未接入的候选底图上保存坐标。底图替换不会自动识别地貌或重算坐标，仍需人工逐点核对；这两个操作均支持会话内撤销。

检查报告增加重复地点 ID、归属错误、缺失／越界锚点及过近标记检查。过近仅为提示，不禁止保存；检查通过不代表地貌与地点含义一致。

## 背景音乐

“背景音乐”页管理 `apps/web/src/lib/audio/bgm.json`，支持试听、时长与体积预览、曲目文件替换、音量校准、来源与授权记录，以及修行／游历／战斗的曲目绑定。保存校验现有素材、配置字段和源文件版本，沿用会话内撤销；不会删除音频文件。新增文件先放进 `apps/web/public/assets/audio/bgm/`，再注册曲目。完整播放行为与资源规则见 [游戏背景音乐](game-audio.md)。

## 数值平衡

“数值平衡”使用当前 V6 人物投影、战斗内核和自动决策，不读取数据库、不改游戏数值。后台 Web Worker 支持取消；切换工作台栏目保留模拟条件、结果和对照，进行中的模拟在后台继续；刷新或离开工作台会终止。单组对战可选双方宗门／流派，宗门矩阵覆盖当前五宗门的 25 组有向对战；每个固定种子交换双方站位。讨伐选择首领与 2～4 人同构筑队伍，不偷偷补入治疗或克制宗门。境界、阶段、普通装备／裸装和参考灵宠均可切换。

构筑复用 `towerReferenceBuild`：普通成长、装备品质 0、固定磐石野猪（主人 10 级起）、空个人功法、经脉深度 0、满血满蓝。此样本不是毕业构筑，也不是玩家实际角色；修改内容 TypeScript 后先重建内部库、重启工作台再模拟。

结果包括胜负平、95% Wilson 胜率区间、回合范围、事件伤害／治疗、单段伤害峰值及目标初始生命比例、回合初受控单位回合比例（含在场灵宠，不等于封印命中率）。同种子交换站位的样本存在相关性，置信区间仅供参考。伤害包含事件中的过量伤害，不含护盾吸收。回合上限、两回合内结束、单段达到初始生命、高控制覆盖和明显胜率偏向是人工筛查提示，不是自动判定 Bug。

选择结果组与种子可重现单局、查看开战面板和逐回合原始事件；报告与完整战报均可导出 JSON。可将当前结果设为会话内对照，仅在模拟配置和规则版本一致时显示胜率差值。报告不自动持久化，也不自动调参。已有参考平衡测试不等于全部境界／流派／装备／功法／灵宠组合经过验收。

## 验证

`pnpm run typecheck` 包含工作台 TypeScript 检查；`pnpm run lint` 包含工作台与索引工具。开发时通过真实本地页面验证检索、关联、资源预览、修改确认和撤销，不新增一次性 E2E 或服务模拟测试。
