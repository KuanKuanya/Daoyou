## 测试服务器准备方案

H5 分发的部署职责：前端构建为 HTML/JS/CSS/素材 ZIP，上传后由 TapTap 平台域名托管；我们仍需部署 NestJS API、PostgreSQL、Redis、NATS，并准备邮件与模型调用服务。TapTap 上传不包含这些后端服务。前端更新需重新上传 H5 包，后端更新需保证与平台已发布前端兼容。若保留独立网页入口，其前端仍需单独托管。平台部署路径、SPA 回退、跨站 Cookie 与流式/WS 请求仍需实际运行验证。

现有 Docker API 部署入口可复用，但当前没有指定目标服务器；以下仅为准备方案，不是已部署状态。

- 使用与现有数据隔离的测试 PostgreSQL、Redis、NATS JetStream 和专用持久卷，运行 Nest API 镜像；不要向公网暴露数据库、Redis、NATS 管理或连接端口。
- 为测试 API 配置 HTTPS 域名和支持 WebSocket、流式响应的反向代理，保持流式接口不缓冲。
- 准备真实 SMTP 服务、服务端 AI provider、Cookie/会话配置、cron secret 和平台实际 origin 白名单；所有密钥仅进入服务端运行配置。
- 记录数据库初始化、版本镜像、备份恢复和回滚步骤；测试角色、数据库和邮件环境不能与本地或正式数据混用。
- 确认服务器和邮件可用后，用明确的 `VITE_API_BASE_URL` 重新构建 H5；先验证登录、邮件验证、资源读取和一条完整奖励路径，再开放玩家测试。
- 服务器租用、域名和资质、邮件/模型服务的预算与主体尚未确定，本轮不购买服务、不修改 DNS 或部署。
